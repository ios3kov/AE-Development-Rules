# AE Development Rules 6.1.0

2026-10-02 · Minor release

Уточняет существующее требование актуальной документации и добавляет явную передачу руководства после выпуска. Не меняет interfaces/schema/routing или macOS/Windows-политику 6.0.0.

## Что изменилось

- REL-DOC-001 в Release §26: применимые инструкции установки/обновления, первого запуска, основного сценария, совместимости и ограничений готовятся до публикации.
- В финальном ответе после подтверждённой публикации ИИ даёт проверенные ссылки на релиз и соответствующее ему руководство, предлагает перейти к инструкции.
- На «что дальше?» сначала проверяет документацию; дополнительные руководства предлагает отдельным конкретным scope. Если инструкции готовы, направляет к ним без придумывания лишней работы.
- Поздно обнаруженный обязательный пробел описывается честно; нет выдуманных ссылок, задним числом поставленного PASS или молчаливой замены artifact/tag.
- Smart Entry, Workflow, requirement registry и release checklist согласованы. Добавлены четыре ручных review cases; их наличие не означает, что модель выполнила их успешно.

## Применение

Начните с [AI_ENTRYPOINT.md](../../AI_ENTRYPOINT.md), затем применимых правил; новый контракт находится в [Release §26](../../profiles/RELEASE.md#пользовательская-документация-и-передача-после-релиза). Обновите принятый baseline осознанно и перенесите актуальный release checklist. Уже начатая сессия ИИ должна получить обновлённые правила явно; опубликованный релиз не обновляет её автоматически.

Для небольшого инструмента достаточно README с нужными инструкциями. Не создавать отдельную документацию ради формальности. Доработка руководства не разрешает новую публикацию или изменение продукта.

Schema manifest 3, project-record 1 и artifact 2 и инструменты сохраняются. Предыдущие версии и Evidence сохраняют исходный scope; они не переобозначаются как проверка 6.1.0. Требования целостности, установки и загрузки без обязательных сертификатов/сервисов остаются прежними.
