## Compatibility and adoption

This is a patch under [Engineering §34](../../core/ENGINEERING.md#34-версия-стандарта-и-фиксация-baseline): mandatory meaning and applicability do not change. Previously compliant 11.0.0 projects remain compliant without a process change. Existing adopted baselines stay pinned until an explicit update; no automatic migration is introduced.

Stable Rule/Requirement IDs, numbered sections, the applicability manifest, routing code, schemas, CLI contracts and existing workflows retain their definitions. Only the human-readable `meaning` of `SKILL-EVALUATION-001` changes in the registry. A version-specific publisher reuses the established exact-main CI, archive verification and publication gates, with the existing regression tests applied to it. Existing project records and tooling need no format migration. Historical tags, releases and Evidence retain their original identity.

The representative request comparison covers the following unchanged outcomes:

| Request | Before and after |
| --- | --- |
| Audit-only | No implementation permission or automatic Discovery interview |
| Light JSX bugfix with confirmed scope | Existing core/profile route; no automatic full profiling or Decision Grill |
| Public micro-helper | Release delivery remains independent of risk; AE checks use the existing applicability contract |
| Internal native milestone | Native review/runtime obligations remain applicable; the milestone does not select Release by itself |
| Explicit reference scopes | Reference Audit remains selected at the requested scope without granting implementation permission |
| Mixed UXP/helper components | Applicable component rules remain combined without duplicate Rule IDs |
