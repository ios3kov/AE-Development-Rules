# AE Development Rules 10.0.0

2026-10-08 · Major process release candidate. Publication is confirmed by the [GitHub Release](https://github.com/ios3kov/AE-Development-Rules/releases/tag/v10.0.0), immutable tag and its exact-commit Evidence, not by this source document alone.

## Changes and compatibility

Conditional Agent Skills §43 introduces independent admission, exact source and whole-package pinning, managed update/rollback/revocation/removal, complete-scan consistency and actual isolation capability checks. This is major under Engineering §34: an existing compliant project that uses external agent extensions may need new admission actions. Ordinary work without extensions keeps its existing process. Process/native SHOULD refinements do not require a second agent or new infrastructure.

The existing agent evaluation protocol now has a bounded subprocess broker, independent receipts, hidden observer checkers, paired baseline/skill cases and tune/select/final partitions. Task/dependency/resource/review validators and original C++17 property/fuzz/units/red-green examples are executable. Reference obligations, Evidence and trusted witness from PR #22 are included without replacing the existing authority. Existing AE render, alpha/depth/color, MFR/SmartFX and actual-host requirements remain.

## Install and first use

1. Obtain the tagged source or a release source archive. Pin both version `10.0.0` and the exact commit reported by the tag and `release-evidence.json`. Validate the archive against `SHA256SUMS.txt`; these are source documents/tools, not an AE plugin installer.
2. Read [AI_ENTRYPOINT.md](../../AI_ENTRYPOINT.md), then the manifest-selected sections for the actual task. Keep the project's accepted Product Spec, decisions and Evidence.
3. If adopting starter-kit tools, copy the complete `starter-kit/scripts` directory with its `lib`/vendor dependencies and corresponding schemas/templates/fixtures/registry. Node.js 22+, Python 3.11+ and zsh for POSIX wrappers are required; native examples require a C++17 compiler. Run `node starter-kit/scripts/self-test.mjs --dry-run` before using a copied kit.
4. A small task without external extensions needs no skill policy. For a skill task, follow [the conditional tool guide](../AGENT_SKILLS_TOOLS.md): inspect local package inventory/scan, independently establish the policy and source pin, match the task and available tools, and only then load admitted resources progressively. No upstream skill, hook, MCP or script is installed automatically.
5. Run the existing evaluation adapter only with independently reviewed runtime/configuration and available required isolation. The owned package example is synthetic; it does not approve an external skill.

## Updating an existing project

Existing 9.x and older baselines remain frozen until explicit adoption. Preserve old Evidence and outstanding requirements. Review the delta, determine which conditional rules apply, update custom allowlists for `AGENT-SKILLS` and the new requirement IDs, and record the new version/commit in the project's existing task/checkpoint.

Manifest schema 3 and existing project/artifact records retain their meaning. New skill/evaluation/task/native records are schema v1: copy their schemas, validators and tests together. Do not reinterpret earlier reference draft records as reviewed current data; migrate them with current exact-byte Evidence and the published reference adapter instructions. Registry fields, source metadata and a locally supplied reviewer name do not authenticate independent custody.

To roll back an adopted standard, explicitly restore the previous project baseline/tools and keep new history. For an installed skill use the managed rollback command only if the preserved version still has valid independent admission; revoked versions cannot be activated. Unknown or modified files are retained.

## Verification and remaining limitations

Publication requires green PR and exact merged-main CI: Ubuntu/macOS/Windows self-test plus reference negative tests. Source archives are made from that exact Git commit, checked against its blobs/file modes, and uploaded with checksums and release Evidence. Source-only distribution does not claim OS installation, SDK registration or AE runtime acceptance.

Offline C++ examples passed ASan/UBSan with 20,000 seeded iterations and red/green detection of their own original defect. Synthetic subprocess tests exercise actual protocol actions and independent checks; they do not establish live-model effectiveness. On Windows, Unix agent-process monitoring and POSIX-permission tests are explicitly skipped; Windows production agent isolation is unsupported. Required unavailable isolation means BLOCKED, not approval.

Live agent, AE and iPhone pilots: NOT_RUN. Built-in observation covers broker actions/results and independent diffs; individually audited denied OS syscalls require a separate reviewed runner. Directory permissions, ACL/xattrs and ownership are not certified by package digests. The stdlib SKILL.md parser blocks unsupported YAML forms rather than reinterpreting them.

[Actual protection audit and owner actions](../AGENT_SKILLS_PROTECTION.md): main protection is reported disabled, no rulesets visible, administrative/environment reviewer details unavailable. Enforced verifier/policy/reviewer custody remains BLOCKED until independently established. This standards release changes no GitHub settings and does not enable safe external-skill execution by itself. Product/market/publication work remains paused; AS is unchanged.
