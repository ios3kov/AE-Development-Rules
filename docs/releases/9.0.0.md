# AE Development Rules 9.0.0

2026-10-06 · Major release

Introduces **DECISION-GRILL / Process §42** and requirement **DECISION-GRILL-001**. When a substantial next step depends on unresolved material user decisions, the agent must resolve them as a dependency-aware design tree rather than guessing or asking an undifferentiated questionnaire.

This is a major release under Engineering §34: a previously compliant 8.x workflow can become non-compliant if it silently chooses a material product/UX/scope decision instead of running the conditional Decision Grill.

## What changed

- Material unresolved choices are represented as a **design tree**.
- The current **frontier** contains only decisions whose prerequisites are already settled.
- Questions are asked in short rounds; dependent questions wait for their prerequisites.
- Every material question includes a recommended answer and the relevant tradeoff.
- Facts available from code, repository state, tools, SDK/API documentation or external primary sources remain the agent's job to research.
- The user is asked for product/UX/scope/permission/acceptance decisions, not for facts the agent can establish.
- Already confirmed decisions are reused and are not reopened.
- Covered bugfixes, local refactors and clear small changes do not trigger an interview.
- Machine routing gains the optional `decision-grill` feature overlay; existing callers that omit it retain previous routing behavior.

## Adoption / migration

Existing 8.x project baselines remain frozen until explicit adoption.

When adopting 9.0.0:

1. Pin both standard version `9.0.0` and the exact release commit.
2. Review ongoing work for unresolved material dependent decisions.
3. Trigger `decision-grill` only where the next substantial spec/design/implementation step depends on those decisions.
4. Preserve existing product contracts and historical Evidence; do not retroactively rewrite prior decisions.
5. Update custom rule allowlists that enumerate Rule Group or Requirement IDs to include `DECISION-GRILL` / `DECISION-GRILL-001` where applicable.

Manifest schema 3 and existing artifact/project-record schemas are unchanged. The new overlay uses the existing optional features mechanism.

## Verification boundary

The release candidate must pass the repository self-test on Ubuntu, macOS and Windows, then the exact merged `main` commit must pass the same CI before publication. Those tests validate repository structure, routing and tooling. They do **not** prove that a particular AI model/configuration will execute the Decision Grill correctly; the manual review cases in `docs/AI_BEHAVIOR_SCENARIOS.md` remain configuration-specific behavioral Evidence.

Existing project/product AE runtime Evidence is not upgraded or reinterpreted by this standards release.
