# AE Development Rules 8.0.0

2026-10-03 · Major release

TASK-CLOSE-001 / Process §11 делает явными список применимых требований/tasks/checks для существенной задачи и финальную сверку перед completion claim. FEATURE-SET-001 / Smart Entry §2.4 задаёт добавление функций в существующую разработку с сохранением текущих обязательств. Это major по Engineering §34: 7.x-compliant workflow без explicit mapping/final reconciliation needs a process update.

## Что изменилось

- [Контроль выполнения](../../core/PROCESS.md#контроль-прохождения-задачи-и-финальная-сверка): requirement → task/block → acceptance → check/phase → candidate/Evidence, фактическое обновление после блоков и сверка всего current scope. Код написан не означает проверку/готовность. Открытые обязательные пункты и их влияние видимы.
- [Новый набор фичей](../../AI_ENTRYPOINT.md#24-новый-набор-функций-в-текущей-разработке): baseline, goals/acceptance, impact, targeted discovery, scope/task/dependency updates, fresh affected checks и согласованная приёмка. Старые требования не отменяются автоматически, deferred work не считается done.
- Актуализированы Workflow, registry, task-state и traceability; добавлен [feature-set change template](../../starter-kit/templates/FEATURE_SET_CHANGE.md) и пять manual review cases. Шаблоны можно встроить в существующие записи; отдельные документы не обязательны.
- Фазовый Validation gate сохраняется: safe user-only вопрос может остаться NOT RUN после пройденных pre-handoff prerequisites. Release acceptance остаётся отдельным полным gate. Нельзя маскировать required prerequisite как deferred check.

## Adoption и migration

Начните с [AI_ENTRYPOINT.md](../../AI_ENTRYPOINT.md). Явно передайте 8.0.0/current adopted commit работающей сессии ИИ и обновите project baseline по §34. 7.x/более ранний baseline сохраняется до осознанного adoption; архивные Evidence не переобозначаются.

Для significant multi-block task добавьте mapping в существующий plan/checkpoint, обновляйте после блоков и выполняйте финальную сверку. Для одной малой правки достаточно компактного acceptance statement и результата проверки. Для новых функций запишите delta/impact/retained obligations и scope-specific discovery: не повторяйте весь Stage 0, если решения покрывают запрос.

Новые requirement IDs `TASK-CLOSE-001` и `FEATURE-SET-001`: обновите собственные allowlists/policies при их наличии. Manifest schema 3, project-record 1, artifact 2 и tool interfaces сохраняются. Новые поля шаблонов не добавлять произвольно в strict JSON schemas; используйте соответствующие spec/status records.

Тестирование взаимодействий/затронутой регрессии определяется actual impact, полный Release Gate остаётся. Старый PASS не переносится на изменённые bytes. Нельзя ослаблять acceptance ради зелёных checks. Поручение на функции не разрешает merge/publication/destructive migration само по себе. Сохраняются cleanup, compatibility и distribution contracts.

Прежние tags/releases/assets/backups сохраняются. Откат adopting project восстанавливает собственный baseline и matching tools/records, сохраняя последующие решения, Evidence и пользовательскую работу.
