## Decision and scope

Current [Release §28 / MAC-001](../../profiles/RELEASE.md#28-macos-дистрибутив-целостность-установка-и-загрузка) accepts unsigned or locally ad-hoc-signed macOS artifacts after the applicable integrity, documented installation and actual host-load checks. [Release §30 / WIN-001](../../profiles/RELEASE.md#30-windows-дистрибутив-целостность-установка-и-загрузка) applies the same identity/install/host-load acceptance to unsigned Windows artifacts. Missing certificate/signing-service access cannot itself create a release blocker on either platform. AI must not demand that access or perform remote signing-account operations as a prerequisite.

System prompts/quarantine state are actual observations, not presumed runtime failures or a promise of warning-free distribution. Real inability to install/load using the declared path still fails the relevant acceptance check. User-system changes remain limited by ownership/authorization. Clean source/artifact identity and the product's safety/runtime checks retain their scope.

This changes a mandatory gate's meaning and breaks the previous checker invocation, so the update is major under Engineering §34. Frozen adopted baselines and existing Evidence are not silently rewritten. Already signed artifacts can still qualify, but previous service checks alone do not replace install/host-load Evidence.

## Tooling migration

Copy the updated scripts/lib, REQUIREMENTS.json and applicable templates together. Artifact records remain schema 2; routing manifest stays 3 and project-record stays 1. MAC-DIST/§28/MAC-001 and WIN-DIST/§30/WIN-001 remain stable IDs with their new meanings.

The new interfaces are:

```sh
zsh /path/to/starter-kit/scripts/macos-bundle-verify.sh ARTIFACT NEW_EVIDENCE_DIR
# Windows PowerShell:
pwsh -File C:/path/to/starter-kit/scripts/windows-release-verify.ps1 -Target ARTIFACT -EvidenceDirectory NEW_EVIDENCE_DIR
```

Run it from the product's own Git checkout. The destination must be new and outside the payload. Both wrappers use `record-artifact.mjs` and `verify-artifact.mjs` to record/verify bytes, types, supported modes and internal symlink boundaries. They do not mutate/sign the artifact or call platform-service commands. PASS means recorded artifact integrity only; actual installation and host load remain NOT RUN until separately observed.

Old macOS local/public and required/na arguments reject with an explicit migration message. Windows `-Output` and `-LocalCheck` are replaced by mandatory `-EvidenceDirectory`; old named parameters reject before collection. Remove these arguments and the old policy environment variable from caller automation; do not reinterpret an old signing report as a new integrity record. Keep historical tools/records together.

`verify-native-effect-bundle-macos.sh` still checks plist, expected exports, nonempty resource files, dependencies and hashes in its structural scope, without a signature prerequisite. `macos-binary-audit.sh` still collects Mach-O architecture/deployment/dependency/symbol metadata; failures of required probes remain PARTIAL/nonzero. `windows-binary-audit.ps1` retains hash and required PE/dependency probes, with PARTIAL/nonzero for missing/failing dumpbin; its signature probe is removed. Neither collector infers AE compatibility or inspects account/certificate state.

## Acceptance and Evidence

- Unsigned app/plugin/pkg/dmg and Windows file payload fixtures must pass integrity checks without invoking account/signature/service commands.
- Changed payload must fail its recorded verification; output reuse/overlap and legacy arguments must reject without replacing Evidence.
- Missing/invalid native structure and failed required Mach-O probes must retain failure behavior.
- Full available local self-test and exact-head platform CI must be recorded, with platform skips distinguished from execution.
- Static/document scans are scoped review inputs. No actual model execution, AE runtime or real distribution test is claimed for this rules edit.

## Windows extension — 2026-10-02

The user's follow-up explicitly removes the same certificate/signature/timestamp prerequisites on Windows. Release §30, WIN-001, process/validation/porting/release templates, source registry and starter-kit instructions follow that decision. The Windows wrapper now uses the same record/verify tools as macOS, and the PE collector omits signature probes.

A13 is updated to require unsigned-file integrity PASS while a signature-probe sentinel throws if invoked. It checks unchanged Evidence on output reuse, changed-byte rejection, overlapping output rejection and legacy parameter rejection; failing dumpbin still records PARTIAL/nonzero. Fixture PASS does not mean a fake .exe is a valid PE package, accepted by a store or loadable in AE.

PowerShell/Windows execution is NOT RUN locally; exact-head Windows CI is required for these cases. Earlier green CI verifies only its original head.
