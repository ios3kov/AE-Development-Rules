## Decision and scope

Current [Release §28 / MAC-001](../../profiles/RELEASE.md#28-macos-дистрибутив-целостность-установка-и-загрузка) accepts unsigned or locally ad-hoc-signed macOS artifacts after the applicable integrity, documented installation and actual host-load checks. Missing Apple account/certificate/service access cannot itself create a release blocker. AI must not demand that access or run remote Apple-account operations as a prerequisite.

System prompts/quarantine state are actual observations, not presumed runtime failures or a promise of warning-free distribution. Real inability to install/load using the declared path still fails the relevant acceptance check. User-system changes remain limited by ownership/authorization. Windows requirements, clean source/artifact identity and the product's safety/runtime checks retain their scope.

This changes a mandatory gate's meaning and breaks the previous checker invocation, so the update is major under Engineering §34. Frozen adopted baselines and existing Evidence are not silently rewritten. Already signed artifacts can still qualify, but previous service checks alone do not replace install/host-load Evidence.

## Documentation and channel boundary

Canonical process/release/UXP guidance, requirement registry, release/validation/porting/UXP templates, adoption example and starter-kit usage follow this policy. The obsolete Apple source entry is removed. [Adobe UXP packaging](https://developer.adobe.com/uxp/guides/how-to/distribution/package/) was read on 2026-10-02; the retained source record covers supported package tooling, format/ID/layout and the distinction between channel acceptance and local host loading. Only that checked source date advances.

External stores have their own acceptance conditions. Do not claim a local build is accepted by every store; choose the agreed delivery path and verify it. This standard does not require access to an external service as a prerequisite for the user's native AE product. Historical releases/audits keep their baseline-specific descriptions and do not reintroduce a current requirement.

## Tooling migration

Copy the updated scripts/lib, REQUIREMENTS.json and applicable templates together. Artifact records remain schema 2; routing manifest stays 3 and project-record stays 1. MAC-DIST/§28 and MAC-001 remain stable IDs with the new meaning.

The new interface is:

```sh
zsh /path/to/starter-kit/scripts/macos-bundle-verify.sh ARTIFACT NEW_EVIDENCE_DIR
```

Run it from the product's own Git checkout. The destination must be new and outside the payload. The wrapper uses `record-artifact.mjs` and `verify-artifact.mjs` to record/verify bytes, types, supported modes and internal symlink boundaries. It does not mutate/sign the artifact or call platform-service commands. PASS means recorded artifact integrity only; actual installation and host load remain NOT RUN until separately observed.

Old local/public and required/na arguments reject with an explicit migration message. Remove these arguments and the old policy environment variable from caller automation; do not reinterpret an old signing report as a new integrity record. Keep historical tools/records together.

`verify-native-effect-bundle-macos.sh` still checks plist, expected exports, nonempty resource files, dependencies and hashes in its structural scope, without a signature prerequisite. `macos-binary-audit.sh` still collects Mach-O architecture/deployment/dependency/symbol metadata; failures of required probes remain PARTIAL/nonzero. It does not infer AE compatibility or inspect account/certificate state.

## Acceptance and Evidence

- Unsigned app/plugin/pkg/dmg fixtures must pass integrity checks without invoking account/signature/service commands.
- Changed payload must fail its recorded verification; output reuse/overlap and legacy arguments must reject without replacing Evidence.
- Missing/invalid native structure and failed required Mach-O probes must retain failure behavior.
- Full available local self-test and exact-head platform CI must be recorded, with platform skips distinguished from execution.
- Static/document scans are scoped review inputs. No actual model execution, AE runtime or real distribution test is claimed for this rules edit.

Results are recorded after execution below; final clean commit and CI identities belong in an external verification record rather than a self-referential source SHA.
