# 11.1.0 — finalized working baseline

Выпуск от 2026-10-09 завершает согласованные исправления после v11.0.1. Исходная точка подготовки — `414998a05784f97b63e90bb78635ea02b3162a4e`, с исправлениями [PR #32](https://github.com/ios3kov/AE-Development-Rules/pull/32). Публикацию и точный итоговый commit подтверждают [GitHub Release v11.1.0](https://github.com/ios3kov/AE-Development-Rules/releases/tag/v11.1.0), annotated tag и приложенное `release-evidence.json`.

## Что завершено

- `preflight` не сообщает PASS без команды проверки проекта: отсутствие проверок возвращает BLOCKED / exit 2; ошибки реально запущенных проверок сохраняются.
- Явный `--docs-only` / `-DocsOnly` отделяет документационную правку от проверки кода. Проверяются staged, unstaged, untracked изменения и, при указанной базе, committed scope; код, конфигурация и special/executable paths не получают этот shortcut.
- Проверка Markdown учитывает поддерживаемые ссылки на разделы, Unicode, повторяющиеся заголовки и explicit anchors. Устаревшие переходы сохранены у актуальных canonical разделов, без дублирования требований.
- [AGENTS.md](../../AGENTS.md) ведёт к единому входу. [Рабочий маршрут](../../guides/PROJECT_EXECUTION.md) объясняет поиск существующих команд и разрешённых возможностей, а [UX-приёмка](../../guides/UX_ACCEPTANCE.md) — ранний прототип и наблюдаемые критерии качества.
- Сохранены действующие требования native/JSX/CEP/UXP/helper, MFR/SmartFX/alpha/HDR, безопасность, точная identity и реальная AE-приёмка. Новых универсальных анкет, обязательного второго агента или полного аудита на каждую правку нет.

## Совместимость и внедрение

Minor по [Engineering §34](../../core/ENGINEERING.md#34-версия-стандарта-и-фиксация-baseline): новые необязательные возможности и исправление исполнения существующих требований. Обязательный смысл, applicability, Rule/Requirement IDs и форматы project records не изменены. Ранее соответствующий 11.0.1 проект не получает нового процесса; принятые baselines обновляются только осознанно.

При обновлении tooling учесть изменение exit semantics: старый пустой preflight мог завершаться успешно; новый требует реальную команду проверки. Настроить непустой `package.json` script `check` или подходящий `scripts/project-preflight.*`. Копировать wrapper вместе с `scripts/lib/preflight-docs.mjs` и остальными зависимостями выбранных инструментов. Успешный `echo` не подтверждает приёмку: scope проверок оценивается по существующему ядру.

Для документации использовать `preflight.sh --docs-only` либо `preflight.ps1 -DocsOnly`. В PR/CI задать `AE_PREFLIGHT_BASE_REF` равным реальной базе сравнения. Без него уже закоммиченные изменения не входят в docs-only scope. Результат этого режима не проверяет содержание документации, код или AE.

## Граница выпуска и практическая оценка

Пользователь явно поручил финализировать и опубликовать правила; практическую проверку разных ИИ он проводит самостоятельно. Реальный multi-model pilot не является prerequisite этого выпуска и не добавляется к обычному plugin workflow. [План пилота](../../packages/agent-evaluation/PILOT.md) остаётся необязательным материалом.

Финализация означает завершённый версионированный baseline, а не обещание безошибочной работы любого ИИ. Реальный pilot и AE runtime для этого source-standard release — NOT RUN; ускорение, универсальная надёжность и переносимость отдельных project runners не объявляются доказанными. Существующие AE runtime gates самих продуктов не отменены.

## Проверки и материалы

Перед публикацией должны пройти все четыре обязательных CI jobs на точном merged commit: Linux, macOS, Windows self-test и Reference Obligation Validator. Новый publisher сохраняет gates 11.0.1 и получает те же четыре отрицательных regression tests. Источники, test skips и ограничения не заменяются выдуманными результатами.

Приложены `AE-Development-Rules-11.1.0.zip`, `AE-Development-Rules-11.1.0.tar.gz`, `SHA256SUMS.txt` и `release-evidence.json` после успешной публикации. Publisher сверяет bytes и file modes обоих архивов с Git tree, проверяет uploaded digests и tag/main identity и только затем открывает stable Release. Старые tags/releases не меняются.
