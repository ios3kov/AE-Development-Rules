## Tooling migration

Copy scripts with lib, relevant schemas and REQUIREMENTS.json together. Node 22+ remains required. New self-test includes `tests/deep-audit.mjs` and checks full authoritative metadata fields, not incidental links. Current normal VERSION has no prerelease/build suffix or leading-zero components, consistent with [SemVer §2](https://semver.org/spec/v2.0.0.html#spec-item-2). README distinguishes checkout candidate from the published stable release.

Routing manifest schema remains 3 and output keys are unchanged. Previously valid contexts retain scope/discovery/reference/delivery behavior. Optional `context.features` is a dense unique array; omit it for the previous caller shape or supply known feature names from the [generated map](../../DEVELOPMENT_RULES.md#conditional-feature-overlays). JSX/helper Light now read TOOL-RUNTIME, Critical CEP/UXP read CODE-SAFETY; state/safety/completion minima still scale to scope. Reading a section does not require every AE/platform test on a documentation edit. Missing task overlays, undefined output IDs or linked canonical files/ancestors now reject. Use an ordinary adopted checkout; do not work around the boundary check by copying external bytes unnoticed.

Artifact record and embedded manifest advance to **schema 2**. POSIX `stat.mode & 07777` includes ordinary permissions and setuid/setgid/sticky bits, which are only metadata observations, not elevated execution tests. Windows mode scope is Node-emulated, not ACL/ownership certification. ACLs, xattrs, uid/gid and timestamps remain outside the recorded contract. New verifier rejects old records explicitly. Preserve v1 record/tool/baseline together, or collect a fresh v2 record against current bytes/state in a new owned destination. Never relabel historical Evidence as covering previously omitted metadata.

AI run snapshot advances to **schema 2** with platform/mode scope, file type/size/hash and directory presence/modes including empty directories. File-scope inspection observes unauthorized metadata changes; parent creation for an authorized file is allowed, existing parent chmod is not implicitly allowed. `.git` internals and other permissions still need actual trace/manual review. Legacy or foreign-platform snapshots reject; retain their original inspector/catalog and prepare a new owned v2 run. Dirty provided standard still needs full snapshot identity, not a claim that HEAD alone identifies it.

Project-record schema remains 1. Sparse/inherited direct-JS arrays are rejected. `uniqueItems` now follows [JSON instance equality](https://json-schema.org/draft/2020-12/json-schema-core#section-4.2.2): object key order is irrelevant, array order is significant. Duplicate Evidence formatting variants reject, without weakening path/hash/revision checks. Comparisons are bounded (64 nesting levels, 100000 nodes); oversized/deep unsupported direct inputs fail closed. JSON CLI remains the preferred serialization boundary.

API collector performs fatal UTF-8 decoding, accepts a valid literal U+FFFD and preserves BOM for lexical text while hashing original bytes. Malformed inputs still fail before output creation; no source file is silently dropped. macOS stapling N/A reason must contain non-whitespace text; substantive text is not proof of actual approval or distribution acceptance.
