# От поручения к проверенному результату

Практический маршрут для [Smart Entry](../AI_ENTRYPOINT.md) и [Workflow](../WORKFLOW.md), не второй нормативный процесс. Не требует отдельного tracker, нового framework или дополнительных агентов.

## Сначала найти рабочий путь

До объявления операции недоступной прочитать существующие README/status, package scripts, build/test runners и применимые CI/release workflows. Проверить доступные инструменты и конкретные операции по их фактическим интерфейсам. Отсутствие одной специальной команды не доказывает отсутствие разрешённого пути.

Пример: нет прямого инструмента создания Release, но в репозитории есть проверенный publisher. При явном поручении «публикуй» допустимо использовать его документированный путь, сохраняя PR/CI/approval gates и точный candidate. Не обходить отказ в правах другим аккаунтом, не ослаблять protection и не считать повторный запрос пользователя исправлением технической ошибки. Нет разрешённого пути — назвать отказ и блокировать только зависимую операцию.

В существующий README/status проекта можно встроить краткую таблицу. Заполнять её найденными и проверенными командами, а не выдуманными путями:

| Операция | Что записать |
| --- | --- |
| Подготовка среды | Реальные toolchain/SDK/host versions, dependencies, безопасная проверка capability |
| Быстрые проверки | Команда, затронутые критерии и явные пропуски |
| Сборка и упаковка | Команды, source/build identity, точный выходной путь |
| Проверка в AE | Runner/fixture, owned session, установленная и загруженная identity, наблюдаемый результат |
| Публикация | Существующий workflow/команда, требуемые права, gates и проверка опубликованных tag/assets |

Запись команды не разрешает её выполнение. Build/preflight должен быть просмотрен перед первым запуском: не запускать скрытую публикацию, установку или разрушительную операцию под видом теста. На continuing task восстановить эту таблицу, не строить аналогичную систему заново.

## Короткий рабочий цикл

Приёмка → минимальный работающий сценарий → небольшое изменение → связанные быстрые проверки → реальный затронутый AE-сценарий при соответствующем утверждении → checkpoint. Для нового продукта сначала подтвердить один основной сквозной сценарий; не считать его полным согласованным продуктом. Независимую работу распараллеливать только при доступной изоляции по Process §5.

Для неопределённого исследования выбрать соразмерный бюджет действий/времени. При отсутствии новой информации менять гипотезу или разрешённый путь по Workflow §9; увеличение retries само по себе не прогресс. Исчерпание бюджета не превращает обязательный тест в N/A/PASS. Полный Release Gate не повторяется после каждого редактирования.

## Preflight: область результата

В полном starter kit используются `scripts/preflight.sh` (zsh) и `scripts/preflight.ps1` (PowerShell). В проект копировать выбранный wrapper вместе с `scripts/lib/preflight-docs.mjs`; зависимости остальных используемых инструментов сохранять как описано в starter-kit README.

Обычный вызов запускает существующий непустой `package.json` script `check` и/или платформенные `scripts/project-preflight.*`. Если ни одной команды проверки проекта нет, результат BLOCKED (exit 2), а не PASS. Ошибка команды сохраняет неуспех. Даже успешно запущенный `echo` не подтверждает нужную приёмку: соответствие выбранных проверок риску оценивается отдельно по Process §1.

Для явно документационной правки: `preflight.sh --docs-only` или `preflight.ps1 -DocsOnly`. Режим проверяет Git whitespace и область staged/unstaged/untracked изменений, а при `AE_PREFLIGHT_BASE_REF` — также diff с базой. Разрешены обычные `.md`, `.rst`, LICENSE/COPYING/NOTICE; code/config, executable documents и special paths блокируются. Без base ref уже закоммиченный scope не оценивается: в PR/CI задавать реальную базу. Это не проверка содержания документации или работоспособности кода. Вывод явно оставляет code/AE: NOT RUN.

## Знания и AE-процедуры

[AAE Developer Bible 1.2.0](https://github.com/ios3kov/AAE-Developer-Bible/tree/e796313877b996a0e8701341e682915c35c6ce94) — закреплённый справочник, не новая копия правил. Читать нужную тему и границы источника; точные target SDK headers и применимые Adobe документы сохраняют приоритет для API. Этот pin не означает актуальность любой будущей версии AE.

[AE know-how](../docs/AE_ENGINEERING_KNOWHOW.md) содержит ссылки на реальные project runners. Перед переносом проверить их source/license, paths, session ownership, host versions, output contract и rollback. Адаптировать только нужный runner и проверить его на целевом проекте. Source review/учебный fixture не устанавливают переносимость или AE PASS. Недоступный host остаётся BLOCKED/NOT RUN, пока наблюдение не получено.
