# Accessibility Checklist

Use proportionally to the UI technology and product scope.

## Keyboard / focus

- [ ] Main actions reachable by keyboard where runtime permits
- [ ] Focus order is logical
- [ ] Focus state is visible
- [ ] No essential action requires precision mouse-only interaction without necessity

## Visual

- [ ] Text/controls remain readable at supported scaling
- [ ] State is not communicated by color alone
- [ ] Contrast is sufficient for critical states
- [ ] Resize does not hide essential controls
- [ ] Hit targets are usable

## Labels / meaning

- [ ] Ambiguous controls have clear labels/tooltips
- [ ] Errors explain what happened and what user can do
- [ ] Icons do not carry unexplained critical meaning alone

## Platform/runtime support

- [ ] Supported AE UI technology limitations documented
- [ ] Screen-reader/accessibility support is claimed only if actually available and tested
- [ ] Relevant OS accessibility settings tested where runtime exposes them
